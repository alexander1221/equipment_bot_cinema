# Выдача оборудования — кафедра кинопроизводства

Telegram-бот для бронирования учебного кинооборудования студентами (с согласованием
у преподавателя и назначением выдачи специалистом) и веб-панель специалиста:
календарь занятости, заявки, инвентарь, внутренние брони. Реализует ТЗ
«Telegram-бот „Выдача оборудования“» и список оборудования ITHub.

Сборка: 2026-10-22, версия 1.0.0.
Проверено: Linux x86_64, Python 3.13 (setup.sh на чистой копии, 60 тестов).
Колёса зависимостей проверены для Windows x64 / Python 3.12–3.13 и Linux / 3.12,
но **на Windows установка не запускалась** и **с настоящим Telegram бот не
запускался** (в среде сборки нет доступа к api.telegram.org) — все сценарии бота
прогнаны через подменённый Telegram API в тестах.

## Как это работает

```
Студент ──/start, курс, ФИО──▶ Бот ──▶ даты (календарь) ▶ преподаватель ▶ проект ▶ техника (чекбоксы)
                                │        бот показывает только то, что разрешено курсу и свободно
                                ▼
                     Преподаватель: «Студент … просит выдать … Подтверждаете?»  [Подтверждаю] [Отклоняю]
                                ▼
                     Специалист: шаблон «25 октября, 14:00, ауд. 106.1» → правит кнопками → «Отправить студенту»
                                ▼
                     Студент получает, где и когда забрать → специалист отмечает «выдано» → «возвращено»
```

Специалист и администратор работают ещё и в веб-панели (по умолчанию `http://<сервер>:8080`).

## Быстрый старт

**Linux / WSL2 / macOS**
```bash
bash setup.sh                  # venv, зависимости, .env, база, проверка, тесты
nano .env                      # BOT_TOKEN, пароли панели
.venv/bin/python main.py run   # бот + панель
```

**Docker** (рекомендуется для сервера кафедры)
```bash
cp .env.example .env && nano .env
docker compose up -d --build
```

**Windows** — двойной клик по `windows_first_run.bat`, подробности в [README_WINDOWS.md](README_WINDOWS.md).

## Первый запуск: что настроить

1. **Создать бота.** В Telegram: @BotFather → `/newbot` → токен в `BOT_TOKEN`.
2. **Пароли панели.** `WEB_SPECIALIST_PASSWORD` (специалист) и `WEB_ADMIN_PASSWORD`
   (администратор — ещё и раздел «Сотрудники»). `WEB_SECRET_KEY` setup-скрипт генерирует сам.
3. **Подключить сотрудников.** Панель → «Сотрудники» (или `python main.py invites`):
   у каждого преподавателя и специалиста своя ссылка `t.me/<бот>?start=inv_…`.
   Сотрудник открывает её — и его Telegram привязан. Пять преподавателей из ТЗ
   и одна запись «Специалист по выдаче» создаются автоматически; полные ФИО
   можно дописать в панели.
4. **Подтверждать студентов.** Каждый новый студент приходит специалисту в бот
   карточкой «ФИО, группа, курс» с кнопками «Подтвердить» / «Курс другой» / «Отклонить».
   То же — в панели, раздел «Студенты». Если ни один специалист не подключён к боту,
   карточки видны только в панели.
5. **Проверить инвентарь.** Панель → «Инвентарь»: количество и уровни доступа
   заполнены из файла оборудования и матрицы ТЗ.

## Правила, заложенные в сервис

| Правило (ТЗ) | Как реализовано |
|---|---|
| Кто может бронировать | Любой может открыть бота и зарегистрироваться, но **заявки подаёт только студент, которого подтвердил специалист** (сверил ФИО, группу и курс со списком). Изменение ФИО/группы/курса снимает подтверждение. Панель → «Студенты» или кнопки в боте |
| Матрица доступа по курсам (п. 2) | Уровень позиции 1/2/3, уровень студента считается по курсу и дате начала брони (`app/access.py`). Курс сам растёт 1 сентября |
| 1 курс — не раньше 1 января | Календарь первокурсника начинается с 01.01; попытка обойти — ошибка |
| Sony FX3/FX30 скрыта | Не показывается студентам; на «FX3», «fx30» и т.п. бот отвечает фразой из ТЗ. Специалист может занять её внутренней бронью |
| Не в прошлом, максимум 14 дней | `MAX_BOOKING_DAYS=14`; также `MAX_ADVANCE_DAYS=90` — не дальше 90 дней вперёд |
| Учёт количества | Подневный расчёт: 10 камер a6400 могут быть у разных студентов одновременно |
| Занятость студентами и внутренними бронями | Заявка блокирует технику сразу после отправки (чтобы два студента не взяли одно и то же). Неподтверждённая заявка закрывается через `PENDING_TTL_HOURS=48` |
| Внутренние брони (п. 3.4) | Панель → «Внутренняя бронь» |
| Изменение и отмена | Панель → карточка заявки: «Изменить даты или состав» (продление, частичный возврат), «Отменить», «Отметить: возвращено» — в любой день, техника сразу снова свободна. Студент может отменить свою заявку и сообщить о досрочном возврате; возврат засчитывает специалист |
| Списание (п. 5.3) | Панель → «Инвентарь» → «Списать»; если после списания брони не помещаются — панель покажет, какие |

Добавлено сверх ТЗ (легко убрать): обязательное название учебного проекта в заявке
(«выдача строго под учебные проекты»); отмена заявки студентом; напоминание о
возврате накануне; учёт просрочки (невозвращённая техника считается занятой);
команды `/today` и `/pending` для специалиста; согласование в панели за
преподавателя, если тот ещё не подключился к боту.

## Структура

```
equipment_bot/
├── main.py                  # точка входа: init-db | run | web | invites
├── app/
│   ├── access.py            # матрица доступа (документирована, с примерами)
│   ├── availability.py      # подневный расчёт занятости
│   ├── validation.py        # ФИО, даты, время
│   ├── services.py          # бизнес-логика (общая для бота и панели)
│   ├── notify.py            # уведомления участникам
│   ├── models.py, db.py     # схема БД, подключение, начальное наполнение
│   ├── seed_data.py         # инвентарь из файла ITHub + матрица ТЗ
│   ├── texts.py             # тексты сообщений и шаблон выдачи
│   ├── jobs.py              # фоновые задачи: истечение заявок, напоминания
│   ├── bot/                 # обработчики Telegram (студент, сотрудники, календарь)
│   └── web/                 # веб-панель (FastAPI + шаблоны Jinja2)
├── tests/                   # 75 тестов: матрица, занятость, сквозные сценарии бота и панели
├── verify_install.py        # проверка установки
├── setup.sh / setup.ps1 / windows_first_run.bat
├── Dockerfile, docker-compose.yml
├── requirements.txt         # прямые зависимости (==, проверены)
├── requirements-lock-*.txt  # полный набор с хэшами под Linux и Windows
└── docs/ARCHITECTURE.md, docs/TROUBLESHOOTING.md
```

`environment.yml` (Conda) не прилагается: все зависимости ставятся из PyPI колёсами,
Conda тут ничего не даёт. `download_*` нет — внешних моделей и данных нет.
