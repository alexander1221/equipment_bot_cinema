# Архитектура

## Бот или Mini App?

Выбран **обычный бот с inline-кнопками + веб-панель для специалиста**. Причины:

| | Бот (выбрано) | Mini App |
|---|---|---|
| Соответствие ТЗ | ТЗ описывает именно бота: inline-кнопки курса, календарь, чекбоксы, кнопки «Подтверждаю/Отклоняю» | Пришлось бы переписывать сценарии |
| Инфраструктура | Только исходящие запросы к Telegram. Не нужен домен и HTTPS | Нужен публичный HTTPS-домен с сертификатом, доступный из интернета |
| Разработка и поддержка | Один язык (Python), нет фронтенда | Отдельный фронтенд (JS), проверка `initData`, вёрстка под телефоны |
| Удобство студента | 4 шага кнопками, ~10 нажатий | Удобнее при большом каталоге (поиск, фото) |

Для 25 позиций кнопок хватает. Если каталог вырастет до сотни позиций или
понадобятся фото техники, Mini App можно добавить поверх того же
`app/services.py` — бизнес-логика не знает про Telegram, её уже используют два
интерфейса (бот и панель).

## Поток данных

```
 Telegram ──long polling──▶ aiogram Dispatcher ──▶ app/bot/*  ─┐
                                                               ├─▶ app/services.py ──▶ SQLAlchemy ──▶ SQLite
 Браузер специалиста ──HTTP──▶ FastAPI app/web/app.py ─────────┘          │
                                                                          ▼
                                             app/notify.py ──▶ Bot API (сообщения участникам)
 app/jobs.py (каждые 10 мин): истечение заявок, напоминания о возврате
```

Всё работает в **одном процессе** (`python main.py run`): бот, панель и фоновые
задачи делят один event loop.

## Почему так

- **Один процесс и asyncio.Lock.** Проверка свободных единиц и запись брони идут под
  одной блокировкой, поэтому две одновременные заявки на последнюю камеру не пройдут
  обе. Для кафедры (десятки заявок в день) этого достаточно. При переходе на
  несколько процессов/серверов нужна блокировка в БД — PostgreSQL и
  `SELECT … FOR UPDATE` по строкам `equipment`.
- **Заявка блокирует технику сразу**, ещё до решения преподавателя. Иначе
  преподаватель мог бы подтвердить две заявки на одну единицу, и конфликт всплыл бы
  только у специалиста. Чтобы забытая заявка не держала технику, она закрывается
  через `PENDING_TTL_HOURS`.
- **Подневный учёт** (`app/availability.py`): количество единиц важно — 10 камер
  a6400, 5 штативов, 5 C-Stand. Брони сравниваются не «пересекаются или нет», а по
  максимуму занятых единиц в каждый день периода.
- **Матрица доступа как «уровень»**: столбцы ТЗ вложены (A ⊂ B ⊂ C), поэтому позиции
  достаточно одного числа 1/2/3. Специалист меняет его в панели без программиста.
- **Курс хранится вместе с учебным годом**: 1 сентября все студенты автоматически
  «переходят» на следующий курс — без ежегодной перерегистрации.
- **Невозвращённая техника занята до возврата** — просрочка не делает её свободной.
- **Сотрудники подключаются по ссылке-приглашению**, а не по списку Telegram ID: ID
  никто не знает наизусть, а ссылку можно переслать.

## Компоненты: что делает и чего не делает

| Модуль | Делает | Не делает |
|---|---|---|
| `access.py` | Уровень студента на дату, допуск позиции, распознавание «FX3» | Не ходит в БД |
| `availability.py` | Подневная занятость, нехватка, перебронь | Не знает о статусах и БД |
| `services.py` | Все изменения состояния заявок, инвентаря, сотрудников | Не отправляет сообщения |
| `notify.py` | Сообщения участникам; убирает кнопки у уже обработанных уведомлений | Не меняет данные заявок |
| `bot/` | Диалоги в Telegram (FSM) | Бизнес-правила — только через `services` |
| `web/` | Панель специалиста | — |

## Статусы заявки

```
pending ──преподаватель──▶ approved ──специалист──▶ scheduled ──▶ issued ──▶ returned
   │  └──отклонил──▶ rejected                │                │
   └──48 ч без ответа──▶ expired              └──────отмена────┴──▶ cancelled
internal (внутренняя бронь) ──▶ cancelled
```

Блокируют технику: pending, approved, scheduled, issued, internal.

## Хранение

SQLite-файл `data/equipment.db` (WAL-режим). Резервная копия — копирование файла
(лучше при остановленном сервисе) или `sqlite3 data/equipment.db ".backup backup.db"`.

Переход на PostgreSQL: `pip install asyncpg` и
`DATABASE_URL=postgresql+asyncpg://user:pass@host/db`. Таблицы создадутся при старте.
Миграций (Alembic) в версии 1.0 нет: схема создаётся `create_all`; при изменении
схемы в будущих версиях понадобится миграция.

FSM-состояния диалогов хранятся в памяти: при перезапуске сервиса незавершённая
заявка (ещё не отправленная) сбрасывается, студент начинает заново. Отправленные
заявки хранятся в БД и не теряются.

## Производительность

Расчёт занятости — O(число пересекающихся броней × дней), периоды ≤ 14 дней.
Шкала в панели — до 62 дней × 25 позиций. Узких мест на масштабе кафедры нет.
