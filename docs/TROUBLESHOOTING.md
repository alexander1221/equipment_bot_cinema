# Типовые проблемы

## Установка

**`Python … not found` / `python3.12: command not found`**
Установите Python 3.12: Ubuntu — `sudo apt install python3.12 python3.12-venv`;
Windows — `winget install -e --id Python.Python.3.12`. Затем
`bash setup.sh --python python3.12`.

**`venv creation failed`** (Debian/Ubuntu) — `sudo apt install python3-venv` (или `python3.12-venv`).

**`pip install … failed`, `THESE PACKAGES DO NOT MATCH THE HASHES`**
Lock-файл собран под Linux x86_64 и Windows x64. На другой платформе (ARM, macOS)
setup.sh сам ставит из `requirements.txt`. Если ошибка хэшей на поддерживаемой
платформе — файл повреждён прокси/зеркалом: `pip install -r requirements.txt`.

**`The SQLAlchemy asyncio module requires that the Python 'greenlet' library is installed`**
Ставили зависимости не из requirements.txt: `pip install greenlet==3.5.6`.

**Windows: «Предупреждение о безопасности … [R] Выполнить однократно»**
Это метка «скачано из Интернета» на файлах из ZIP. Лучше до распаковки:
`Unblock-File .\equipment_bot.zip` (или «Свойства → Разблокировать»). Если уже
распаковано — в папке проекта `Get-ChildItem -Recurse | Unblock-File`, либо
запуск через `windows_first_run.bat`. Ответ `R` безопасен.

**Windows: кракозябры вместо `...` в выводе установки**
Конфликт кодировок cp1251/cp866 в консоли. Скрипты выводят только ASCII, так что
это не должно случаться — сообщите версию Windows и язык системы.

## Запуск

**`BOT_TOKEN не задан в .env`** — заполните `.env` (образец `.env.example`).

**`Telegram отклонил BOT_TOKEN`** — токен скопирован не целиком или отозван.
@BotFather → `/mybots` → бот → API Token.

**`Нет связи с Telegram Bot API (… Cannot connect to host api.telegram.org:443 … Превышен таймаут семафора / timeout)`**
Боту нужен HTTPS до api.telegram.org (TCP-порт 443). Ping это **не проверяет**: ping
(ICMP) может проходить, а 443 — блокироваться провайдером или сетью вуза.
Проверка на Windows:
```powershell
Test-NetConnection api.telegram.org -Port 443      # TcpTestSucceeded : False — порт закрыт
curl.exe -sI https://api.telegram.org               # зависает / ошибка — то же самое
```
Linux: `curl -sI https://api.telegram.org`. Если порт закрыт — варианты по порядку:
1. **Прокси / VPN на этом компьютере.** Python **не** использует системный прокси
   Windows, даже если браузер и Telegram Desktop через него работают. Укажите прокси
   явно в `.env`: `TELEGRAM_PROXY=socks5://127.0.0.1:<порт>` — порт смотрите в настройках
   своего VPN/прокси-клиента (у многих клиентов это локальный SOCKS5 или HTTP-порт).
   Подходит и внешний прокси: `socks5://user:pass@host:1080`, `http://host:3128`.
   Если VPN работает в режиме «весь трафик через туннель» (TUN), прокси не нужен —
   проверьте `Test-NetConnection` при включённом VPN.
2. **Запустить сервис на сервере, откуда Telegram доступен** (сервер кафедры/вуза с
   открытым доступом, облачный VPS). Для постоянной работы так и правильнее: бот должен
   работать, когда ноутбук выключен. `docker compose up -d`.
3. Попросить ИТ-службу открыть исходящий HTTPS к api.telegram.org.

**`Прокси … не пропустил запрос к Telegram`** — неверный адрес/порт/тип прокси
(`socks5://` vs `http://`) или клиент VPN не запущен. Проверка:
`curl.exe -x socks5h://127.0.0.1:<порт> -sI https://api.telegram.org`.

**`TelegramConflictError: terminated by other getUpdates request`**
Бот с тем же токеном запущен где-то ещё (второй сервер, ноутбук разработчика).
Остановите лишний экземпляр.

**Панель: «Пароль панели не задан»** — заполните `WEB_SPECIALIST_PASSWORD` /
`WEB_ADMIN_PASSWORD`, перезапустите.

**Панель «выкидывает» после перезапуска** — не задан `WEB_SECRET_KEY`.

**Панель не открывается с другого компьютера** — `WEB_HOST=0.0.0.0`, порт
`WEB_PORT` открыт в файрволе. Для доступа из интернета ставьте перед панелью
nginx/Caddy с HTTPS: пароль по HTTP передаётся открытым текстом.

## Работа

**Преподаватель не получает заявки.** Он не открыл свою ссылку-приглашение
(панель → «Сотрудники», колонка Telegram), или заблокировал бота. Пока он не
подключён, специалисты получают предупреждение и могут согласовать заявку в панели.

**Студент пишет «профиль не подтверждён», а специалисту ничего не приходит.**
Ни один специалист не подключён к боту (панель → «Сотрудники») — карточки студентов
тогда видны только в панели → «Студенты» и в сводке.

**Студент поменял курс — и снова не может бронировать.** Так задумано: любое
изменение ФИО, группы или курса отправляет профиль на повторную проверку.

**Студент не видит нужную позицию.** Либо она недоступна его курсу на эту дату
(панель → «Инвентарь», уровень), либо занята (панель → «Календарь»), либо скрыта.

**Первокурсник не может выбрать дату осенью** — так задумано ТЗ: с 1 января.

**Студент ошибся с курсом** — специалист исправляет курс в панели → «Студенты» (или студент через `/profile`, после чего профиль проверяют заново).

**Узнать свой Telegram ID** (для `ADMIN_IDS`) — команда `/id` в боте. В `ADMIN_IDS` пишутся только числа: `@username` бот использовать не может.
